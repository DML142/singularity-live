# Global shortcuts and binds settings implementation plan

**Goal:** Deliver the approved hotkey, Binds settings, and development-launcher behavior as a bounded follow-up to transient screenshot assistance. A user can invoke an explicit screenshot action globally, review it in the existing UI, and configure an unbounded list of shortcut bindings. Development setup stays ephemeral and does not persist credentials.

**Architecture:** Rust owns binding validation and persistence, OS shortcut registration, cursor-to-monitor resolution, capture and window hide/restore, permission/error state, cancellation, provider requests, and cleanup. Windows/macOS/Linux X11 use Tauri's global-shortcut plugin; Linux Wayland uses the existing `ashpd` dependency's XDG GlobalShortcuts portal because the plugin's underlying Linux backend is X11-only. React owns settings presentation, explicit chord-recording interaction, and preview rendering. The dev launcher is a Node script that selects an implemented local workflow and passes environment values only to the spawned Tauri process. Screenshots remain in the existing Rust transient image store and use the existing provider/session boundary.

**Tech Stack:** Tauri 2, Rust, `tauri-plugin-global-shortcut`, existing XCap/XDG portal capture adapters, React 19, strict TypeScript, Vite/Vitest, Node built-ins, existing Rust mock backends/providers.

**Spec:** `docs/superpowers/specs/2026-09-27-global-shortcuts-settings-design.md`

**Global Constraints:** Do not modify the original checkout's existing user changes. No automatic/hidden capture or automatic send. Never put screenshots or credentials in logs or persistent config. Do not add OCR, audio, transcription, VAD, SQLite, credential storage, tray mode, startup registration, or future actions. Wayland portal consent/selection stays system-visible; do not claim a binding is registered until the portal confirms it. No live provider calls in tests or verification. Preserve Phase 3 as `Not started` and Phase 4 as `In progress`; mark this feature complete only after automated checks and available manual smoke verification pass.

**Review Focus:** Verify chord validation matches what the UI can record and the OS plugin/Wayland portal can accept; failed updates restore runtime registrations and prior persisted config; a hotkey capture hides the app before one explicit frame and restores it on success, error, and cancellation; screenshot bytes never enter logs or text history; the CLI does not echo or persist API keys and argument mode never prompts; all UI calls are narrowly permissioned.

## Task 1: Add the binding domain and persistent settings store

**Files:** `src-tauri/src/shortcuts/mod.rs`, `src-tauri/src/shortcuts/model.rs`, `src-tauri/src/shortcuts/store.rs`, `src-tauri/src/lib.rs`, Rust unit tests in the shortcut modules.

- Define `ShortcutAction` (`Screenshot` only), `ShortcutBinding`, and `ShortcutChord` with stable binding IDs, an optional chord for a cleared/unregistered row, and typed key/modifier values. A chord is zero to two modifiers plus one trigger key, which represents one to three simultaneously pressed keys; it is never a sequence.
- Parse and validate supported physical key names, reject Escape as an assigned trigger, reject repeated modifiers, empty non-cleared chords, chords longer than three simultaneous keys, unknown actions, duplicate chords, and empty configurations. Permit duplicate actions.
- Add a versioned JSON configuration store under Tauri's app-config directory, seeded with `Ctrl + Super + P` on platforms where `Super` is the platform's Windows/Command key equivalent. Use write-to-temp plus atomic rename; tolerate a missing file by using defaults, and report malformed/read/write errors safely.
- Public service shapes: `ShortcutBindings::defaults(platform) -> Vec<ShortcutBinding>`, `validate_bindings(&[ShortcutBinding]) -> Result<(), BindingError>`, `ShortcutConfigStore::load() -> Result<Vec<ShortcutBinding>, BindingStoreError>`, and `ShortcutConfigStore::save(&[ShortcutBinding]) -> Result<(), BindingStoreError>`.
- Tests cover serialization/versioning, defaults, chord limits, Escape clearing, duplicate chord rejection, repeated actions acceptance, malformed files, and atomic replacement failure preserving the previous file.

**TDD:** Write domain and store tests first, run the targeted Rust test filter, then implement until they pass. Avoid creating empty files or placeholder APIs; wire each module into `lib.rs` when compiling its first test.

## Task 2: Register shortcuts transactionally and expose settings commands

**Files:** `src-tauri/Cargo.toml`, `src-tauri/Cargo.lock`, `src-tauri/src/shortcuts/registrar.rs`, `src-tauri/src/shortcuts/service.rs`, `src-tauri/src/commands/shortcuts.rs`, `src-tauri/src/commands/mod.rs`, `src-tauri/src/lib.rs`, `src-tauri/capabilities/main-window.json`, `src-tauri/permissions/autogenerated/`, `src-tauri/tests/command_permissions.rs`.

- Add and initialize the official Tauri global-shortcut plugin for Windows/macOS/Linux X11. On Linux Wayland use `ashpd::desktop::global_shortcuts::GlobalShortcuts`, whose system portal confirms the effective trigger and emits activation events. Keep registration and callbacks in Rust. Translate typed chords at the platform adapter boundary and surface a visible unavailable/denied state when the portal is missing or rejects registration.
- Define an async `ShortcutRegistrar` port with `register_available(bindings)`, transactional `replace(bindings)`, and `unregister_all()` operations. Startup registration can return usable and failed rows independently; updates either establish all requested chords or preserve the old set. Production adapters use the Tauri plugin or XDG portal and tests use a deterministic fake that simulates conflicts, portal consent, and rejection.
- Define `ShortcutBindingService` to load defaults/configuration and expose each row's registration state. Persist only after a candidate set has validated and registered. When a candidate fails, unregister its partial registrations, restore all previous registrations, retain the previous config, and expose a safe row-level error. On startup, keep valid bindings registered and report invalid/conflicting rows individually.
- Add typed `get_shortcut_bindings` and `update_shortcut_bindings` commands. Grant only those command permissions to the main window; the plugin callback remains Rust-only and is not webview-callable.
- Tests cover registration, unregistration, duplicates, simulated OS conflicts and portal rejection, partial registration rollback, persistence rollback, startup with one invalid binding, effective trigger/status handling, and generated command permissions.

**TDD:** Add fake-registrar service tests before runtime implementation. Verify that every failed update leaves the previously active binding set and settings file unchanged. Exercise the portal adapter with a mockable portal-session port; no desktop bus is required in tests.

## Task 3: Add cursor monitor resolution and the hide-capture-restore coordinator

**Files:** `src-tauri/src/capture/backend.rs`, `src-tauri/src/capture/mod.rs`, new Rust modules under `src-tauri/src/shortcuts/` for capture coordination and cursor adapter, `src-tauri/src/lib.rs`, Rust unit tests.

- Add a testable `CursorPositionProvider` and `MonitorResolver` boundary. On X11, Windows, and macOS, obtain the global pointer position through a supported platform adapter and resolve its containing XCap monitor; return a safe unavailable error if no monitor contains it. On Wayland, continue using the user-visible XDG ScreenCast picker and its explicit consent/source selection; do not use XCap's file-backed path.
- Reuse the existing `ScreenCaptureService` and transient store. Expose a Rust operation for capturing the resolved monitor without accepting a target identifier from React.
- Define a small `CaptureWindow` port and `HotkeyCaptureCoordinator` that rejects busy starts, hides the main window, requests one monitor frame, restores visibility/focus/always-on-top, and emits one typed preview or safe error event. Restore runs on every success/error/cancellation path; clear transient data if restoration or capture fails. An already active manual capture/request is reported as busy and is not duplicated.
- Use a Rust-generated operation ID and existing cancellation token semantics. Bind cancellation to window close and explicit app shutdown; do not introduce hidden/background capture.
- Tests use fake cursor/monitor/window/capture adapters to verify monitor choice, hide-before-capture-before-restore ordering, active/minimized restore, error/cancellation cleanup, busy rejection, and no retained image after a failed path.

**TDD:** Define tests against adapter ports first. No test may invoke a real desktop capture backend or provider.

## Task 4: Connect global activation and complete the native window lifecycle

**Files:** `src-tauri/src/lib.rs`, `src-tauri/src/shortcuts/service.rs`, `src-tauri/tauri.conf.json`, Rust tests where practical.

- Install a Rust global-shortcut pressed-event callback that maps the registered chord to its action and dispatches the screenshot coordinator. Ignore release events.
- Resolve the main window at startup, set always-on-top, and reapply always-on-top after showing/focusing it after hotkey capture. Report a safe startup/window error rather than silently dropping a shortcut.
- Ensure hotkey activation emits preview/error status to the same existing screen-assistance UI; it does not submit the image. The existing five-minute TTL, crop, explicit send/discard, reset, and exit cleanup remain unchanged.
- Keep the capture callback independent of React and do not ship image bytes through logs or diagnostic strings.

**TDD:** Use coordinator and service fakes to test event-to-action dispatch and ignored release events. Keep platform window tests as adapter-level tests if the headless environment cannot instantiate a Tauri window.

## Task 5: Add the Binds settings view and hotkey preview state

**Files:** `src/app/App.tsx`, new `src/features/settings/` components and tests, `src/lib/tauri/shortcut-client.ts` and tests, `src/stores/screen-assistance-store.ts`, `src/features/assistant/AssistantPanel.tsx`, `src/app/styles/global.css`, `src-tauri/src/commands/shortcuts.rs` event payloads.

- Replace the disabled Settings button with an in-app settings view containing a Binds tab. Keep the assistant accessible from the existing window; do not create a second native window or add model/key settings.
- Render any number of binding rows with stable IDs, one row always retained, add/remove-row actions, a single `Screenshot` action option, row-level registration/errors, and clear/reset state.
- Record a chord only while the user has activated that row's capture control. Collect supported simultaneous modifier+trigger keys into at most three physical keys; Escape clears and is not assigned. Cancel recording on blur/unmount. Display the platform-specific modifier label.
- Add a typed IPC client that validates untrusted IPC responses without `any`, and a small bindings store/hook for loading/updating state. React never registers OS hotkeys, hides windows, selects monitors, or orchestrates capture.
- Add a typed Rust event listener for hotkey preview/error results and hydrate the existing screen-assistance preview state, ensuring it uses the current display/error lifecycle and explicit send/discard controls. Do not add image bytes to conversation state or persist them in browser storage.
- Tests cover row add/remove invariants, chord recording and Escape, safe error/status rendering, IPC schema rejection, and receiving a hotkey preview without sending it.

**TDD:** Add component/store/client tests before UI behavior. Validate keyboard recording in a focused test that simulates 1-, 2-, and 3-key chords and Escape.

## Task 6: Add the ephemeral development launcher

**Files:** `scripts/dev-assist.mjs`, `scripts/dev-assist.test.ts`, `package.json`, `README.md` or a focused developer workflow section.

- Add a single convenient package command (for example `pnpm assist`) that with no arguments presents implemented local task choices for manual text or screenshot assistance, asks only for missing non-secret values, and accepts a missing OpenRouter key through non-echoing TTY input.
- Launch `pnpm tauri dev` as a child with the collected environment. Do not write `.env`, config, history, or logs. Do not accept a key flag or print a key. Keep direct `pnpm tauri dev` unchanged.
- If any arguments are supplied, parse explicit task/model/context-pack options, skip all prompts, require `OPENROUTER_API_KEY` already in the environment, and fail clearly when required values are absent. Never treat unknown options or key-like values as a credential input.
- Keep task selection a launch preset only: it cannot trigger a capture or provider request by itself. The context pack must already exist; the launcher never creates or overwrites user context files.
- Tests inject input/output/spawn adapters and verify argument/no-argument branches, hidden key input without echo, no key persistence or CLI argument acceptance, child env delivery, and no launch on missing required config. Tests never require a real API key or desktop runtime.

**TDD:** Add launcher tests before CLI implementation. Keep launcher logic separately testable from actual process spawning and raw-terminal handling.

## Self-review

- The seven task groups cover all nine acceptance criteria from the spec: activation/minimized flow, always-on-top/no self-capture, monitor resolution and Wayland consent, arbitrary bindings and chord recording, conflict/persistence behavior, transient preview and cleanup, CLI secret handling, automated coverage, and manual platform smoke testing.
- New Rust/React/CLI boundaries and their public operations are named above; adapter seams allow tests to avoid OS capture and real network calls.
- Credentials remain process-environment-only. Bind settings persist only non-secret shortcut values. Image bytes remain Rust transient data and the explicit preview channel.
- No Phase 3 work, Phase 4 completion, OCR, SQLite, product credential UI, tray mode, or automatic capture is planned.
- Review focus is covered directly by the fake registrar, capture/window/cursor ports, IPC permission tests, CLI injected adapters, and final diff/security review.
